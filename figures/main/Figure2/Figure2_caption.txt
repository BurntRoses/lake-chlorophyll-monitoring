Figure 2. Shared residual-tree learning and quota-constrained lake selection.
(a) Environmental inputs, fixed base-model logits and a window identifier enter a shared residual-tree ensemble. The three outputs correspond to 31–60, 1–14 and 15–30 days; the 31–60-day output determines the monitoring list. Miniatures show saved trees 1, 2 and 60, and the enlarged tree shows the full topology of tree 1 with raw residual leaf values. Split labels abbreviate transformed inputs: TP, total phosphorus; Chl-a, chlorophyll a; Window ID, lead window. Input blocks are schematic. The dashed pathway indicates training feedback, with auxiliary loss weights of 0.1 relative to the primary weight of 1. Training, leaf scaling and full split definitions are given in Supplementary Methods S2 and the source data.
(b) Left: deployment scores for 2,805 eligible lakes on 25 June 2023; the top-k rule selects 281 lakes, marked in ochre. Right: eligible opportunities for events A, B and C are pooled so that selection on any one opportunity contributes event-level coverage. Smooth selection weights sum to each round’s integer quota. Known labels contribute classification loss, while candidates with unknown outcomes remain in the ranking and receive a base-prediction constraint (Supplementary Methods S2).
(c) Splits by input family across the 60 trees of each fitted ranker. Columns represent trees and cells count splits, using a shared 0–7 colour scale. Multi-window trees use both base predictions and the window identifier as splitting variables. Source data give the family assignments and counts.
The learning schematic was drawn with Python/SVG code assisted by OpenAI Codex (OpenAI). Tree topologies and counts were read from the fitted models.
